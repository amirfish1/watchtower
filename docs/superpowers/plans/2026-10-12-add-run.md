# Add --run Implementation Plan

> **For agentic workers:** Use executing-plans to implement this single task inline.

**Goal:** Let a filer request immediate dispatch with `wt add --run`.

**Architecture:** Record a run request using `queue.mark_runnable` before the
existing add dispatch. Use the current reconciler and eligibility rules for
both file and GitHub queues, without changing their policy.

**Tech Stack:** Python stdlib and pytest.

## Global Constraints

- Stdlib-only Python, zero runtime dependencies — keep it that way.
- Shared main checkout: develop in the sibling `watchtower-wt-add-run` worktree.
- Push each commit immediately; never bypass the pre-push test gate.
- Leave grace periods, dependencies, readiness, planning, and capacity policy intact.

  ```python
  if getattr(args, "run", False):
      try:
          runnable = q.mark_runnable(item["ref"])
      except Exception as exc:
          print(f"error: filed {item['ref']}, but could not request its run: {exc}",
                file=sys.stderr)
          return 1
      if runnable is None:
          print(f"error: filed {item['ref']}, but could not request its run: ticket not found",
                file=sys.stderr)
          return 1
      item = runnable
      print(f"RUNNABLE: {item['ref']}  {item.get('title') or item.get('note', '')}")
  ```
